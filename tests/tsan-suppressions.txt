# ============== 2. QtDBus global-init vs its manager worker ==============

# 2.1 The 0x1d43ee class (×3 in the P1 selection): main thread allocates
# inside qDBusBindToApplication() (libQt6DBus+0x3b647, addr2line — the
# once-per-process bus bind) while the QDBusConnection worker frees at
# libQt6Core+0x1d43ee (allocator internals; addr2line's nearest symbol,
# QMimeData::qt_metacall, is bogus — the frame is unexported). QtDBus's
# global bus-init races its own manager thread; both racing frames are
# runtime-invisible, so the entry anchors on the only symbolized dispatch
# frame common to every occurrence (the queued meta-call that triggered
# the bind). Tripwire: fires only for tests whose bus init happens inside
# a queued slot invocation — a new geometry shifts the stack and fails loud.
# ANCHOR NOTE: invokeImpl also appears in 4.1-class stacks; TSan counts a
# report against one matching entry — see 4.1's anchor note.
# Evidence: p1-tsan-test_dbus-testConnectionLossHandling.log (initTestCase
# :491), p1-tsan-test_adaptor-testOwnerChangeAnchorSpyTiming.log,
# p1-tsan-test_dbus-testLossProbeIdleTraffic.log; parent-tree parity: same
# class at parent offsets 0xde77f/0x1d5ba1 (council-punch report §P1);
# isolation: iso-proxynowatch.log (0x1d43ee fires without any watcher).
race:QMetaMethodInvoker::invokeImpl
