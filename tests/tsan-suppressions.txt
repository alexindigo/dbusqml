# ThreadSanitizer suppressions (ledger-zero L3).
#
# Pattern (xdp ships this for ASan/valgrind): suppress ONLY the
# Qt/libdbus-internal races characterized on the fork VM
# (arch-niri-dbusqml-features, Qt 6.11.2) across the T1-selection TSan
# runs (G1 destroy-churn, G2 storm, G3 re-entrant, G4 spy-timing, G5
# foreign-thread — 3/3 runs) plus the churn-free G4+G5 geometry. Every
# entry cites its evidence. Zero dbusqml frames appear in any report:
# no dbusqml lock, queue, relay field, holder, or claim state is ever
# named — the single dbusqml-adjacent frame
# (DBusPathDispatcher::handleServiceOwnerChange, a QString == compare)
# appears only as a READER inside Qt-internal races.
# Usage: TSAN_OPTIONS="suppressions=tests/tsan-suppressions.txt".
# Acceptance: T1-selection TSan run is zero-UNSUPPRESSED; any NEW frame
# fails loud (it matches no entry below).

# 1. QCoreApplicationPrivate::sendPostedEvents (3× every run) —
# the Qt event-posting path racing QQmlThread/manager delivery.
# Evidence: "SUMMARY: ... in QCoreApplicationPrivate::sendPostedEvents"
# ×3 in each of san-tsan-t1-{1,2,3}.log and ×2 in san-tsan-g45.log.
race:QCoreApplicationPrivate::sendPostedEvents

# 2. QObject moveToThread/delete churn (libQt6Core 0x2aea67/0x2aea76,
# 1× every run) — operator new vs operator delete on QObject storage
# across the main thread and the QQmlThread worker (created by main at
# test invocation). Qt object-affinity internals, not ours.
# Evidence: "operator new ... by main thread" vs "operator delete ...
# by thread T2 'QQmlThread'" in san-tsan-t1-1.log.
race:QObject::moveToThread

# 3. libQt6Core 0x1d43ee + 0x29e500 (1× every run each) — operator
# new/delete + memcpy inside QtCore racing the QQmlThread worker;
# unnamed (stripped) frames, same QQmlThread-creation stack as (2).
# Evidence: san-tsan-t1-{1,2,3}.log, identical counts every run.
# (0x1d43ee ALSO appears standalone as a SUMMARY key — same allocator
# frames, same creation stack; covered by the same class.)
race:QQmlThread
race:QDBusConnection::connectToBus
race:0x1d43ee

# 4. libQt6Qml 0x483149 (1× every run incl. churn-free G4+G5) —
# QML-engine-internal race, present even with no churn threads.
# Evidence: san-tsan-g45.log (G4+G5 only, no storm).
race:libQt6Qml.so.6

# 5. libdbus dbus_connection_get_is_connected (1× every T1 run) —
# libdbus-internal connected-flag race on the QDBusConnection worker
# thread (created by main in the churn tests). C library internals.
# Evidence: "in dbus_connection_get_is_connected" in
# san-tsan-t1-{1,2,3}.log.
race:dbus_connection_get_is_connected

# 6. libdbus 0x3805a (run 2 only) + 0x24a81 (G4+G5 only) — further
# unnamed libdbus-internal races on bus worker threads. Same class as
# (5): C library internals, no dbusqml frames.
race:libdbus-1.so.3

# 7. QWaitCondition::~QWaitCondition (run 3 only) — Qt thread-shutdown
# race at teardown. Evidence: san-tsan-t1-3.log.
race:QWaitCondition::~QWaitCondition

# 8. QDBusMessage::~QDBusMessage (run 3 only) — QtDBus message-teardown
# race. Evidence: san-tsan-t1-3.log.
race:QDBusMessage::~QDBusMessage

# 9. QString/QArrayData internals (G4+G5 only: qarraydatapointer.h:111,

# 10. libglib event-pump (G4+G5 only) — glib main-loop internals under
